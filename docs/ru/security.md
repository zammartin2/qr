## Сообщение об уязвимости

О проблемах безопасности сообщайте приватно на **security@devorbit.ru**. Опишите проблему, шаги воспроизведения, затронутые версии и известные последствия. Вы получите подтверждение в течение 3 рабочих дней.

Не открывайте публичный GitHub issue для сообщений, чувствительных с точки зрения безопасности.

Формальная политика — в [SECURITY.md](../../SECURITY.md) в корне репозитория.

## Модель угроз

Это локальная библиотека, а не сервис. Предполагается, что вызывающая сторона контролирует вход и путь вывода. Песочницы, rate-limit'а и валидации семантики полезной нагрузки нет — кодирование фишингового URL в QR-символе сознательно вне области (см. [SECURITY.md](../../SECURITY.md)).

## Цепочка поставок

- **Ноль рантайм-зависимостей.** Опубликованный пакет исполняет только собственный код и встроенные модули Node.js: `node:zlib` (сжатие PNG), `node:fs/promises` и `node:path` (`qrToFile`), `node:buffer` (node PNG entry). `npm audit --omit=dev` на чистой установке проверять нечего.
- **Dev-зависимости** (TypeScript, tsup, vitest, eslint, typedoc, size-limit, `qrcode` для parity-тестов) влияют только на разработку и CI. Они не попадают в `dist/`, а `node_modules` никогда не публикуется.
- **Публикуемые артефакты:** `dist/`, `docs/`, `README.md`, `LICENSE`, `CHANGELOG.md` и `package.json` — проверьте локально через `npm pack --dry-run`.
- **Lockfile закоммичен.** `package-lock.json` в репозитории, поэтому `npm ci` ставит точное, воспроизводимое dev-дерево в CI.
- **Воспроизводимые генерируемые таблицы.** Таблица EC-блоков и таблица kanji (Unicode → Shift JIS) создаются закоммиченными скриптами (`scripts/gen-ec-table.mjs`, `scripts/gen-kanji-map.mjs`) и проверяются тестами против независимых оракулов на каждом запуске CI.
- **Укрепление CI.** Workflow'ы GitHub Actions используют закреплённые **мажорные версии** action'ов (`actions/checkout@v4` и т.д. — не SHA), тестовый job идёт на матрице 3 ОС × 3 Node, а публикация — только из workflow `Publish` по событию `release: published` с `NPM_TOKEN`. Job'ы `bench`, `decode`, `bun` и `deno` выполняются только на Ubuntu. npm provenance (`--provenance`) сейчас не включён.
- **Гейт аудита.** CI запускает `npm audit --omit=dev` на чистой установке; ожидается ноль находок.

## Поверхность атаки рантайма

- Вход — обычная JS-строка, кодируемая в UTF-8. Ввод `Buffer` / `Uint8Array` не принимается — вызывающая сторона должна декодировать сначала. `eval`, динамического импорта пользовательских данных и shell-out'ов нет.
- **Чрезмерно большой вход** падает с `RangeError` на этапе выбора версии. Сервис, выставляющий `generateQR` недоверенному вводу, должен ограничивать длину до вызова: ёмкость QR до 2 953 байт (v40, EC L), поэтому больше гарантированно не влезет — но ошибка происходит после того, как вход уже скопирован во внутренние буферы.
- `qrToFile` пишет только по пути, переданному вызывающей стороной. Валидация пути — её ответственность (это локальная библиотека, не сервис).
- **Цвета SVG** XML-эскейпятся, поэтому недоверенные значения `dark`/`light` не могут внедрить разметку через `<`, `>`, `&`, `"`, `'`. Учтите: цвета SVG принимают любую CSS-строку — включая `url(...)` — поэтому, вставляя SVG в живой DOM, относитесь к строкам цветов как к недоверенному вводу.
- **Цвета PNG** проходят через строгий парсер `#RGB` / `#RRGGBB`; всё остальное бросает `RangeError`.
- **Sourcemap'ы в сборку не выпускаются** (`tsconfig.build.json` задаёт `sourceMap: false`) — проверьте через `npm pack --dry-run` перед публикацией.

## Известные CVE

По состоянию на 2026-10-08 — нет. У пакета нет стороннего рантайм-кода, который мог бы содержать CVE.
