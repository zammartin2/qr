## Development setup

```bash
git clone https://github.com/zammartin2/qr
cd qr
npm install
```

Requirements: Node.js ≥ 18 (the `engines` field enforces this on install).

## Project layout

```text
src/
  core/                 ISO/IEC 18004 pipeline — no platform APIs
    generate.ts         public generateQR entry point
    matrix.ts           function patterns → data placement → mask → format
    alignment.ts        alignment pattern placement (incl. the v32 case)
    version.ts          version selection, capacity, version BCH(18,6)
    format.ts           format BCH(15,5) and placement
    mask.ts             8 masks, N1–N4 penalty, automatic selection
    rs.ts               Reed–Solomon encoding + block interleaving
    gf.ts               GF(256) log/antilog tables
    ec-blocks.ts        ISO Table 9 (auto-generated — do not edit)
    encode/             numeric, alphanumeric, byte, kanji
    constants.ts        mode/EC bits, char-count widths, remainder bits
    types.ts            public types (type-only, no runtime)
  platform/             compression backends
    deflate-node.ts     node:zlib (sync)
    deflate-browser.ts  CompressionStream (async)
    detect.ts           hasCompressionStream()
  render/               output formats
    ascii.ts, svg.ts, terminal.ts
    png/{shared,node,browser}.ts   PNG encoder split by compressor
    file/{node,stub}.ts            qrToFile and its browser stub
  index.ts              universal entry (default condition)
  index.node.ts         Node / Deno / Bun entry
  index.browser.ts      browser / Workers / Edge entry
```

The three entry points are intentionally thin — they only re-export from `core/`, `render/` and `platform/`. All real logic lives in those modules so it can be tested once and shared.

## Before opening a pull request

Run the same gates CI runs:

```bash
npm run lint              # eslint, zero warnings allowed
npm run typecheck         # tsc --noEmit
npm run test:coverage     # must keep thresholds green
npm run build             # tsup must produce dist/
npm run test:bundle       # esbuild drift guard + d.ts contract checks
npm run docs:check        # every public export must carry JSDoc
npm run analyze           # gzipped ESM must stay under 100 KB
```

`npm run test:bundle` is the most important gate to understand: it bundles the browser and universal entries with `--platform=browser` and asserts there are no `node:*` imports, then bundles the Node entry the same way and asserts it fails (drift guard). It also checks the `.d.ts` contracts (`qrToPNG` returns `Buffer` in node types, `Promise<Uint8Array>` elsewhere) and resolves every export condition against the built output.

## Testing

```bash
npm test                         # vitest run
npm run test:watch               # watch mode
npm run test:coverage            # with coverage report
npx vitest run path/to/file.test.ts  # single file
```

Coverage thresholds live in `vitest.config.ts`. They are configured as a floor; the project currently holds 100% statements / branches / functions / lines (`src/core/types.ts` is excluded — it is type-only and has no runtime code). A change that drops any metric below the floor fails CI.

**Parity tests against qrcode.** The suite includes a 1280-cell matrix comparison (v1–40 × EC × mask) against `qrcode@1.5.4`. If you touch the generation pipeline (matrix, mask, RS, format/version info, placement), expect to add or adjust a parity assertion. See [docs/compliance.md](docs/compliance.md) for the verification strategy and the list of interpretation choices that are pinned to the reference.

**Property-based tests.** A seeded fuzz run (200 random strings) covers automatic version + mask selection. New detection or capacity logic should extend the fuzz corpus rather than hard-code more cases.

**End-to-end.** CI also renders a QR through both the Node and browser entries and decodes it with OpenCV. If you change the PNG encoder, make sure the decode job still passes.

## Generated tables

Two files under `src/core/` are auto-generated and must not be edited by hand:

- `src/core/ec-blocks.ts` — ISO/IEC 18004 Table 9, regenerated by `npm run gen:ec-table`.
- `src/core/encode/kanji-table.ts` — Unicode → Shift JIS, regenerated by `npm run gen:kanji-map`.

If you need to change either, change the generator script and re-run it:

```bash
npm run gen:ec-table
npm run gen:kanji-map
git diff --stat   # verify the generated diff matches your intent
```

Commit the regenerated file together with the script change. Do not hand-edit the table; a follow-up regeneration would silently revert it.

## Documentation

Published docs live in `docs/`:

| File | Contents |
| --- | --- |
| `docs/api.md` | Public API reference |
| `docs/browser.md` | Browser / edge support and the environment matrix |
| `docs/compliance.md` | ISO/IEC 18004 scope and interpretation choices |
| `docs/examples.md` | Practical recipes |
| `docs/migration.md` | Migrating from qrcode, qrcode-generator, others |
| `docs/performance.md` | Benchmarks and bundle-size methodology |
| `docs/security.md` | Supply-chain and runtime attack surface |

Error messages cross-reference docs. Several runtime errors point at `docs/browser.md` (for example the `qrToFile` stub and the missing `CompressionStream` error). If you change such a message or the behavior it describes, update the referenced doc in the same PR.

**README badges.** The `tests-<N>` and `coverage-<N>%` badges in `README.md` are updated manually. Bump them in the release PR.

## Guidelines

- **Zero runtime dependencies.** Node built-ins only (`node:fs`, `node:zlib`). New dev dependencies need justification in the PR.
- **Spec first.** Changes touching the QR pipeline must reference the clause in ISO/IEC 18004 and, where possible, add a parity test against the qrcode reference or a documented ISO anchor.
- **Tests with the change.** Every new branch needs coverage; keep the thresholds green.
- **JSDoc on public exports** (`npm run docs:check` enforces it). Private helpers may use `@internal`.
- **No breaking API changes without a major version bump;** see [docs/migration.md](docs/migration.md).
- **Keep the three entries in sync.** A new public export must be added to `index.ts`, `index.node.ts` and `index.browser.ts` (or deliberately omitted from the browser entry with a documented reason). `test:bundle` will catch a missing `.d.ts` counterpart.
- **Determinism.** Same input + same options must produce byte-identical output across platforms and Node versions. Do not introduce runtime table generation that depends on ICU or locale.

## Commit messages

Imperative mood, concise, scoped:

```text
fix(matrix): skip timing column in zigzag placement
feat(render): add half-block terminal output
docs(browser): document the Vercel Edge PNG limitation
test(mask): cover N3 with light areas on both sides
```

Common scopes: `core`, `matrix`, `mask`, `rs`, `format`, `version`, `encode`, `render`, `png`, `svg`, `terminal`, `ascii`, `file`, `platform`, `build`, `ci`, `docs`. Use `!` after the scope for a breaking change, e.g. `feat(png)!: qrToPNG is async outside the Node entry`.

## Continuous integration

Every push to `main` and every PR runs:

| Job | What it checks |
| --- | --- |
| `test` | 3 OS × 3 Node matrix: lint, typecheck, coverage, build, analyze, test:bundle, `npm audit --omit=dev` |
| `bench` | Runs the benchmark suite (informational) |
| `decode` | Renders PNG via Node and browser entries, decodes with OpenCV |
| `bun` | Smoke test: `qrToPNG` returns a `Buffer` under Bun |
| `deno` | Smoke test: node entry works under Deno 2.x |

If a job fails, the job name tells you which contract broke. `test:bundle` failures usually mean an accidental `node:*` import reached the browser entry, or a `.d.ts` signature drifted.

## Reporting bugs

Open a GitHub issue with a minimal reproducer: input text, options, expected vs actual output (a matrix dump or rendered file helps).

**Security issues — do not open a public issue.** See [SECURITY.md](SECURITY.md).

## Release process

1. Update `CHANGELOG.md` (Keep a Changelog format).
2. Bump the version in `package.json` (semver) and update the `tests-<N>` and `coverage-<N>%` badges in `README.md` if they changed.
3. Run the full prepublish gate locally:

   ```bash
   npm run prepublishOnly
   ```

4. Verify the tarball contents:

   ```bash
   npm pack --dry-run
   ```

   Confirm `dist/`, `docs/`, `README.md`, `LICENSE`, `CHANGELOG.md` are present and that no `src/` or test files leaked in.
5. Tag a GitHub release — the Publish workflow runs lint, typecheck, coverage, build and `npm publish`.
